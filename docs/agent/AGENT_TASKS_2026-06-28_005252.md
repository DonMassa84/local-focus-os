# Local Focus OS — Agent Tasks

Stand: 2026-06-28_005252

## 1. Situation

Local Focus OS hat mehrere Releases, Dashboard UI, Kaizen Workflow System und Regular Operations Workflows. Offene Aufgabe: alte Kaizen-Dashboard-Inhalte in das neue Dashboard integrieren und als reproduzierbaren lokalen Workflow dokumentieren.

## 2. Goal SMART

Innerhalb einer lokalen Arbeitssession wird die Aufgabe **Altes Kaizen-Dashboard in neues Dashboard integrieren und portfoliofähig dokumentieren** so umgesetzt, dass sie reproduzierbar, prüfbar und portfolio-sicher dokumentiert ist.

## 3. Stakeholders

- Operator: Daniel / Schattenmacher
- Repo: Local Focus OS
- GitHub / Portfolio: nur sanitizte Ergebnisse
- Human Review: Pflicht vor Push, Release oder Screenshot
- AI-Agent: Planung, Strukturierung, Dokumentation, Qualitätskontrolle

## 4. Causes

### Human
Mehrere parallele Systeme erzeugen Kontextwechsel und Prioritätsverlust.

### Organization
Aufgaben sind über Chat, lokale Reports, Docs und Git verteilt.

### Process
Ohne Agent-Orchestration fehlt ein reproduzierbarer Ablauf von Analyse bis Kontrolle.

## 5. Alternatives

### A — Minimal Fix
Nur den nächsten Fehler beheben.

### B — Dokumentierter Fix
Fehler beheben und dokumentieren.

### C — Agentischer Repo-Workflow
Aufgabe in Model, Tools, Memory, Audio, Guardrails und Orchestration zerlegen.

## 6. Evaluation

### Economic
C spart Wiederholungsarbeit und macht das Ergebnis portfoliofähig.

### Human
C senkt kognitive Last und gibt klare nächste Aktionen.

### Organizational
C erzeugt ein prüfbares Repo-Artefakt.

## 7. Decision + Justification

Entscheidung: **C — Agentischer Repo-Workflow**

Begründung:
Die Aufgabe soll nicht nur erledigt, sondern wiederholbar, testbar und sicher dokumentiert werden.

## 8. Implementation

### Model

Rolle:
Technischer Repo-Agent für Local Focus OS.

Aufgabe:
Altes Kaizen-Dashboard in neues Dashboard integrieren und portfoliofähig dokumentieren

Arbeitsstil:
präzise, sicher, klein commitbar, keine unnötige Komplexität.

### Tools

Erlaubte lokale Tools:

```text
git
grep
find
bash
markdown
repo-interne scripts
optional: gh cli nach Auth-Fix
```

Nicht automatisch ausführen:

```text
git push
gh release create
rm -rf kritische Pfade
Veröffentlichung von Screenshots
Veröffentlichung von Rohdaten
```

### Memory

Bekannter Kontext:

```text
Local Focus OS hat mehrere Releases, Dashboard UI, Kaizen Workflow System und Regular Operations Workflows. Offene Aufgabe: alte Kaizen-Dashboard-Inhalte in das neue Dashboard integrieren und als reproduzierbaren lokalen Workflow dokumentieren.
```

### Audio

Kein Audio erforderlich.

Falls später Audio/Video/Transkript ergänzt wird:
- Fakten extrahieren
- Aufgaben ableiten
- Unsicherheiten markieren
- keine erfundenen Zitate

### Guardrails

```text
- Keine Secrets committen.
- Keine Tokens veröffentlichen.
- Keine privaten lokalen Pfade in Portfolio-Ausgaben.
- Keine personenbezogenen Behörden-, Gesundheits- oder Finanzdaten.
- Kein GitHub-Push ohne git status + Review.
- Screenshots nur nach Leak-Test.
- Unsicherheiten sichtbar markieren.
```

### Orchestration

Ablauf:

```text
1. Repo-Status prüfen
2. Aufgabe isolieren
3. kleinste sichere Änderung bestimmen
4. lokale Tests / Checks ausführen
5. Dokumentation aktualisieren
6. git diff prüfen
7. Human Review
8. Commit vorbereiten
9. optional Push / Release
```

## 9. Control

Kontrollpunkte:

```text
1. Dashboard zeigt Kaizen-Status.
2. Reports sind verlinkt.
3. Keine privaten Pfade in Portfolio-Dateien.
4. README/Portfolio-Summary bleiben konsistent.
5. git diff ist klein und reviewbar.
```

Standard-Checks:

```bash
git status --short
git diff --stat
git diff --check
git ls-files | grep -E '(^|/)\.venv/' && echo "[FAIL] .venv tracked" || echo "[OK] no tracked .venv"
grep -RInE '(sk-[A-Za-z0-9]|ghp_[A-Za-z0-9]|/home/|/mnt/|C:\\Users|dmassa|Daniel Massa)' . --exclude-dir=.git --exclude-dir=node_modules --exclude-dir=.venv || true
```
